How it works

Does less, so it never surprises you.

Most software is built to handle every possible case, and pays for that on every single operation. These parts handle one case very well, with a fixed size and no room for a surprise.

01

One writer, one reader

When only one side writes and one side reads, there is no need to coordinate between many of them. Accepting that limit is exactly what makes it fast.

02

Memory taken up front

All the memory is claimed when your program starts, never while it is working. You pay that cost once, not in the middle of handling your busiest moment.

03

Right tool, not a general one

A holder that only keeps the newest value behaves nothing like a queue that holds one item. Different problems, different parts.

Modular by design

Pick only the parts you need.

Each library does one job and states plainly what it will and will not do. Take one, take several, leave the rest.

Numbers and identifiers

Exact values, no rounding

  • nexus-bitssmall whole numbers packed tight, no wasted space
  • nexus-decimalmoney maths with no rounding drift
  • nexus-idunique identifiers, generated and read back fast
Passing data between threads

No waiting, no locks

  • nexus-queuefixed-size queues that never block
  • nexus-slota slot that only ever holds the newest value
  • nexus-notifywakes another thread and drops the stale updates
Live statistics

Running totals, no memory growth

Averages, trends, drift detection and smoothing, all updated one value at a time. Each one uses the same fixed amount of memory whether it sees a hundred values or a billion.

Machine learning

Predictions in under a microsecond

Twelve kinds of trained model run directly on the processor, with no graphics card needed. Load models you trained elsewhere and get an answer back in well under a microsecond.

Networking

You stay in control of the connection

  • nexus-netWebSocket and HTTP, you own the socket
  • nexus-async-netready-made async version that reconnects itself

Why Nexus

Why teams choose it.

It tells you what it will do

Every library writes down its limits. Nothing quietly asks the system for more memory, nothing grows without a ceiling, nothing stops to talk to the operating system when you did not ask it to.

The slow moments stay rare

Anyone can look fast on average. These are tuned so the worst moments stay close to the normal ones, measured under real load rather than in a test built to flatter them.

Take only what you need

Each library stands on its own and pulls in almost nothing else. Want the value holder without the scheduler? Take just that one.
